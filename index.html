DevOps Chaos Sandbox

Time-leashed spontaneous failure injector & alerting system for DevOps/SRE learning tracks

Overview

The DevOps Chaos Sandbox runs background systemd timers on your target virtual machines, simulating common infrastructure faults (port blockage, network latency, resource leakages, database failures) under controlled constraints.

⏰ Leashed Execution

The scheduler verifies the current local time falls inside the student's slot (e.g. Sat/Sun 12:00-18:00) before triggering failures, preventing distraction during working/sleeping hours.

💬 Instant Alerts

A monitoring daemon polls the local web application port. It fires instant downtime and recovery warnings to the student's personal Telegram Bot.

Installation & Bootstrap

Run the installation script as root on the target VM:

sudo bash -c "$(curl -sSL https://raw.githubusercontent.com/shapovalovdev/devops-chaos-sandbox/main/installer.sh)"

Available Outage Scenarios

The sandbox triggers one of the following scenarios randomly every 30 minutes during slot windows:

  • kill_database.sh: Terminates PostgreSQL container/service and disables auto-restart.
  • inject_latency.sh: Adds 1.5s delay to connection ports on localhost via tc.
  • disk_exhaust.sh: Safely fills up log partitions leaving exactly 100MB headroom.

Restoration Recipes

If you are triaging an outage, you can clear the injected faults using these commands:

# Reset latency
sudo tc qdisc del dev lo root

# Clear disk exhaustion files
sudo rm -f /var/log/system-journal-cache.tmp

# Restart postgres docker
sudo docker update --restart=always postgres && sudo docker start postgres
